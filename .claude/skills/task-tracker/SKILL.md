# Трекер задач

Пользователь ведёт работу в своём трекере (приложение из этого репозитория). Ты подключаешься к нему
как участник совместной работы над проектом — через CLI `tools/tracker/tracker.mjs`.
Твои правки сразу видны в браузере пользователя, а когда тебя нет, он работает по актуальным статусам.

## Как это устроено (коротко)

- CLI — участник проекта, как ещё один браузер. В режиме P2P команда за ~3 с входит в комнату,
  получает свежие данные, применяет правку и выходит. В трекере появится участник «Claude».
  Если в `state.json` есть `serverUrl`, те же команды ходят на командный сервер (токен человека и
  парольная фраза). Подробности — `docs/team-sync.md`.
- Данные сливаются по полям (побеждает последнее изменение), поэтому правки пользователя и твои
  не затирают друг друга.
- Нужен браузер с открытым трекером и включённой совместной работой над проектом (кнопка «Вместе» →
  «Начать совместную работу»). Если его нет, команда работает с локальной репликой, пишет ⚠,
  а правки уйдут при следующем `sync`. **Обязательно скажи пользователю**, если правки остались
  неотправленными.

## Первый запуск

```bash
npm install --prefix tools/tracker          # если нет tools/tracker/node_modules
node tools/tracker/tracker.mjs setup "<ссылка-приглашение проекта>"
```

Ссылку-приглашение попроси у пользователя: кнопка «Вместе» → «Ссылка-приглашение» → «Скопировать».
Привязка хранится в `tools/tracker/state.json` (не в git). Если команда пишет
«Сначала: setup…» — значит, привязки нет, попроси ссылку.

## Команды

Запускай из корня репозитория: `node tools/tracker/tracker.mjs <команда>`.

| Команда | Что делает |
|---|---|
| `info` | проект, статусы (колонки), спринты, люди |
| `list [--all] [--status S] [--assignee me\|<имя>] [--sprint active\|backlog] [--type T] [--label L] [--json]` | задачи по колонкам; завершённые скрыты без `--all` |
| `show WEB-12 [--json]` | задача целиком: описание, подзадачи, комментарии |
| `create --title "..." [поля]` | создать; по умолчанию первая колонка, приоритет medium, автор — ты |
| `update WEB-12 [поля]` | изменить поля |
| `move WEB-12 <статус>` | сменить статус: название (можно часть), id или `todo` / `in_progress` / `done` |
| `comment WEB-12 "текст"` или `--file F` | комментарий (Markdown) |
| `delete WEB-12` | удалить |
| `chat "текст"` | сообщение в чат проекта |
| `sync` | только синхронизироваться |

Поля: `--type epic|story|task|bug|subtask`, `--priority highest|high|medium|low|lowest`,
`--status S`, `--assignee me|none|<имя>`, `--labels a,b` (заменить) / `--add-label L` / `--remove-label L`,
`--points N|none`, `--due YYYY-MM-DD|none`, `--parent WEB-3|none`, `--sprint active|backlog|<имя>`,
`--desc "Markdown"` или `--desc-file F`. `--offline` — не ходить в сеть.

Ключ можно писать без префикса: `12` = `WEB-12`.

Длинные описания и комментарии (многострочный Markdown) пиши во временный файл в scratchpad
и передавай через `--desc-file` / `--file` — так не будет проблем с кавычками в shell.

## Как работать с трекером

1. **Перед работой** по задаче из трекера: `show <KEY>` — прочитай описание и комментарии.
   Если пользователь просто говорит «займись чем-нибудь» — `list --sprint active`, бери задачи
   из «К выполнению» по приоритету, назначенные на тебя или ни на кого.
2. **Взял задачу** → `update <KEY> --assignee me --status in_progress`.
3. **По ходу**: нашёл баг или follow-up, который не делаешь сейчас, — заведи задачу
   (`create`, тип `bug`/`task`, в описании — где и что, со ссылками на файлы `src/...:строка`).
   Большую задачу дели на подзадачи (`--type subtask --parent <KEY>`).
4. **Закончил** → `comment` с итогом: что сделано, какие файлы, коммит, как проверить, что не
   сделано. Затем статус: если в проекте есть колонка ревью (см. `info`) — туда, чтобы пользователь
   проверил; иначе в `done`. Если работа не закончена — оставь в работе и опиши в комментарии,
   на чём остановился.
5. **Заблокирован** (нужно решение пользователя) — комментарий с вопросом и сообщи в ответе.

Правила:
- Не удаляй и не переназначай чужие задачи, не меняй их приоритет и спринты без просьбы
  пользователя. Свои (созданные тобой или назначенные на тебя) веди сам.
- Не создавай дубликатов: перед `create` проверь `list --all` на похожие названия.
- Названия задач — коротко, по-русски, в повелительном или назывном виде («Починить вход по ссылке»).
- После серии правок кратко перечисли пользователю, что поменял в трекере (ключи и статусы).

## Если что-то не так

- «В комнате никого нет» — браузер закрыт или совместная работа выключена. Работай с репликой
  (`--offline` для скорости) и предупреди пользователя; потом `sync`.
- «Статус/человек/спринт не найден» — сообщение перечисляет доступные варианты, выбери из них.
- Ошибка загрузки `node-datachannel` — `npm install --prefix tools/tracker` (это нативный модуль WebRTC).
- Протокол и проверки изменений описаны в `src/app/core/p2p/` (protocol.ts, scope.ts) и
  `docs/p2p-sync.md`. CLI повторяет их вручную: если поменяется схема данных или протокол
  в приложении, обнови и `tools/tracker/tracker.mjs`.
