# Командный режим

P2P остаётся режимом по умолчанию: браузеры соединяются напрямую, сервер с данными не нужен.
Этот режим — для случая, когда нужен общий журнал. Один человек может быть офлайн, второй
всё равно увидит его правки, когда выйдет в сеть.

Переключатель в **Настройках → Как синхронизировать**:

| Режим | Когда |
| --- | --- |
| Вместе | Браузеры в сети одновременно. Данные через них не проходят на чужой сервер |
| Сервер | Свой VPS. Журнал лежит у вас, обновления приходят сразу |
| Dropbox | Общая папка. Обновления подхватываются каждые несколько секунд |

Общими становятся только проекты, у которых нажато **«Вместе»**. Остальные с устройства не уходят.
Ссылка-приглашение по-прежнему только открывает проект. Токен и парольная фраза в неё не входят.

## Парольная фраза

Одна на команду. Из неё на каждом устройстве получается ключ шифрования. На сервер и в Dropbox
уходят закрытые поля: названия, описания, комментарии, сообщения чата, имена людей, метки,
названия спринтов и статусов.

Открытыми остаются служебные поля: идентификаторы, статус, приоритет, порядок, сроки, часы слияния.
По ним видно структуру проекта, но не текст.

Без парольной фразы сервер и Dropbox не включаются — чтобы текст случайно не ушёл открытым.

## Сервер

Каталог `server/`. Node.js 22, одна зависимость (`ws`).

```bash
cd server
npm install
npm start
```

Сервер слушает `127.0.0.1:8787`. При первом запуске создаёт владельца и записывает его токен
в `server/data/owner-token.txt`. Файл больше не перезаписывается. Токен показывается один раз.

Дальше владелец в приложении (роль видна в настройках) выдаёт остальным свои токены:

- **Редактор** читает и меняет общие проекты.
- **Только чтение** читает. Сервер отвергает запись, приложение не сохраняет правки общих проектов.

Отозвать токен можно там же. Последнего владельца удалить нельзя.

Снаружи порт Node не открывают. Перед ним — Caddy или nginx с HTTPS, прокси на `127.0.0.1:8787`.
В настройках приложения адрес вида `https://sync.example.com`. Если VPS не должен быть виден из
интернета вообще, оставьте его только в Tailscale или закройте файрволом: токен при этом всё равно нужен.

Переменные:

| Переменная | Зачем |
| --- | --- |
| `HOST` | По умолчанию `127.0.0.1` |
| `PORT` | По умолчанию `8787` |
| `DATA_DIR` | Каталог журнала. Не кладите его в git |
| `ORIGIN` | Список адресов сайта через запятую. Пусто — принимать любой Origin, доступ всё равно только по токену |

WebSocket не умеет заголовок Authorization из браузера, поэтому токен уходит первым кадром после
подключения, не в адресе. В логах прокси его нет.

Повтор той же правки журнал не раздувает: клиент прикладывает хеш открытого изменения, сервер
помнит хеши и не хранит сам текст.

### Yandex Cloud, для проверки

Сервер держит соединения в памяти и рассылает правки сразу, поэтому его не ставят в Cloud Functions:
там процесс засыпает и сокеты не живут. Для теста хватает одной маленькой виртуальной машины.
Консоль после команды покажет её в Compute Cloud.

Нужны [CLI Yandex Cloud](https://yandex.cloud/ru/docs/cli/quickstart) (`yc init`, выбран каталог со
счётом) и запущенный Docker.

```bash
node server/yc-up.mjs
```

Команда собирает образ, кладёт его в Container Registry и поднимает машину: 2 ядра на 20%, 1 ГБ,
публичный адрес. В конце печатает адрес и токен владельца. Повторный запуск вторую машину не создаёт.
`node server/yc-up.mjs --recreate` удаляет машину и поднимает пустую: токен новый, журнал пустой.
`--preemptible` дешевле, но облако может остановить машину в течение суток.

Без домена адрес вида `http://<ip>:8787`. Его принимает локальный `npm start`. Сайт на GitHub Pages
открыт по https, и браузер не пускает такую страницу на http. Pages и облако при этом не мешают
друг другу: Pages по-прежнему отдаёт само приложение, облако хранит только журнал. Связка — адрес
сервера в настройках сайта.

Для сайта нужен домен, который вы контролируете. У регистратора создайте A-запись, например
`sync.example.com`, и поднимите машину заново:

```bash
node server/yc-up.mjs --domain sync.example.com --recreate
```

Перед Node встаёт Caddy и сам получает сертификат. В настройках на сайте укажите
`https://sync.example.com`, токен и парольную фразу. Токен один раз попадает в серийный лог машины:
его видят те, у кого есть доступ к каталогу. `--origin https://user.github.io` дополнительно
принимает запросы только с этого сайта. Путь страницы (`/task-tracker/`) в origin не входит.

### Любой VPS

Та же схема без Docker и без Yandex Cloud. На компьютере нужен только клиент SSH.
Машина — Ubuntu, Debian или другой Linux с systemd и bash. Команда копирует сервер
на VPS и ставит Node.js 22. С доменом перед ним встаёт Caddy и сам получает сертификат.

```bash
node server/vps-up.mjs root@203.0.113.10 --domain sync.example.com
```

Без `--domain` сервер слушает `http://<ip>:8787`, его откроет локальный `npm start`.
A-запись домена должна указывать на этот VPS без прокси. Повторный запуск обновляет
файлы и не стирает журнал. Токен владельца печатается в конце; если сервер уже
запускался, это прежний токен.

## Dropbox

1. В [консоли Dropbox](https://www.dropbox.com/developers/apps) создайте приложение с доступом к файлам.
2. Выпустите access token и вставьте его в настройках вместе с парольной фразой и папкой
   (по умолчанию `/task-tracker`).
3. У каждого устройства свой файл `<id устройства>.jsonl` в этой папке. Два браузера не пишут
   в один файл, поэтому Dropbox не делает «конфликтные копии».

Папка должна быть доступна только этой команде. Токен Dropbox — это доступ к ней, парольная фраза
закрывает содержимое.

## Описание задач

Одновременные правки описания больше не затирают друг друга целиком. В задаче хранится снимок
текстового CRDT (`descriptionState`), а строка `description` — то, что из него получилось.
Правки разных мест складываются и в P2P, и на сервере, и в Dropbox.

## Терминал

`tools/tracker` умеет тот же сервер. При привязке:

```bash
node tools/tracker/tracker.mjs setup "<ссылка>" --server https://sync.example.com --token "<токен>" --passphrase "<фраза>"
```

Дальше обычные команды ходят на сервер, а не в P2P-комнату. Токен «только чтение» правки не отправит.
